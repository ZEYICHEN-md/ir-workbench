# 需要人手取的数：从哪儿拿

> **迁移说明（2026-08-25）**：从旧仓 `travel-weekly-report/references/manual-acquisition.md`
> 与 `workbook-update.md` 搬入。
>
> **第一次迁移漏了。**新 SKILL 只说了底稿哪几列要填、读表规则是什么，
> **没说这些数每周从哪里来**。接手人会知道 W/X/Y 三列该有值，
> 但不知道找谁、去哪个公众号、抄哪几个数——**每周固定动作直接断掉**。

## 周度：飞常准（微信公众号）

对应底稿机票**周度**块的 客运量 / 票价 / 客运航班量。**只在微信里能拿。**

1. 微信 → 搜索 → 公众号：**飞常准大数据**（飞友科技旗下）
2. 关注后看每周推送（《中国民航市场简报》或周度客运数据）
3. 摘取周度的**民航客运量同比 / 票价同比 / 客运航班量同比**，填底稿周度块

为什么走公众号：飞常准官网（variflight.com、data.variflight.com）与 CADAS 是付费产品，
**公开网页没有稳定的周度页**。

## 周度：航班管家（微信公众号）

对应出境与国际**运力**（周度），底稿「国际航班运力（航班管家）」列。

1. 微信 → 搜索 → 公众号：**航班管家**
2. 看每周运力推送，摘取**国际航班运力同比**等，填底稿

## 周度：酒店 STR

现已改由中金周报按天加权算出（见 [SKILL.md](../SKILL.md) 的中金链）。
**这是有意换的路，不是漏迁**——已论证周度 K/L/M 与人手抄值逐位一致。
STR 官方月报太慢，不等它。

## 月度：航空

走 `aviation-monthly` 域自动抓官方（民航局 + 三大航公告），不用人手抄。
发布节奏：三大航约每月 15–16 号，民航局约 20 号后。

## 旧的「测算 → 官方」口径切换规则：随五部分周报一起停用

旧仓有一条规则（`data-sources.md`「测算→官方 口径切换」+ `industry-data-section-redesign`
ADR-002/003）：月度客运量官方发布慢，**非发布周先用第三方测算口径顶上、标「测算口径」，
不留空窗**；官方发布后正文切官方值并加注新旧值与旧值来源；允许 Agent 自动切；
方向相反或差异异常大时停下问人。

而工作台现在的规则是相反的：**抓不到就返回 `blocked`，不要手工推算**
（`modules/aviation_monthly/SKILL.md`）。

**裁定（2026-08-25）：旧规则停用，新规则有效。**两条不是同一件事，分开看就不冲突：

| | 旧规则的场景 | 现在的场景 |
|---|---|---|
| 数写到哪 | 五部分周报 §二 的**正文叙述** | **指标底稿**（唯一真源，ADR 0001） |
| 为什么要顶上 | 那一节每周必须有个数，空着难看 | —— |
| 空着的代价 | 读者看到空行 | 看板月度那格空着 |

往**底稿**里塞测算值是另一回事：底稿是唯一指标真源，塞进去之后所有下游（看板、飞书、
洞察）都会把它当实测值用，而「这是测算口径」这个限定只活在当初那句正文注解里。
五部分周报已停用，那个「每周必须有个数」的需求也一起没了。

所以：**官方没发布就空着。**若将来确实需要「非发布周不留空窗」，那是**看板呈现层**
的问题（在图上标「官方未发布」），不是往底稿里写测算值。

一并作废的还有那条「允许 Agent 自动切换口径」——现在没有要切的东西了。
但**「方向相反或差异异常大时停下问人」这条判据仍然有效**，它已经落在
`conventions/data-provenance.md` 的数据冲突处理里。

## 一条口径提醒：周度票价与月度票价不可直接比

飞常准的**周度**票价与航班管家 / 民航局的**月度**票价，来源与统计周期都不同。
各用各的场景，**方向相反属正常**，不要当成数据错误去「修正」。

## 人工兜底：Excel COM 不可用时怎么手填

正常路径是 `ir aviation run --commit`（Excel COM 全量重算）。COM 不可用时人接手，
规矩是：

- 月份列：Jan = B、Feb = C … Dec = M
- **只填绝对量。**同比与三大航合计（Big 3 Total）都是**公式**——
  **不要手填覆盖公式**，覆盖了下次重算就回不来了
- 填完**必须用 Excel 或 WPS 打开再保存**，否则公式缓存不刷新，脚本读到的还是旧值
- 自检：`G3 ≈ G11 + G19`（合计 ≈ 国内+地区 与 纯国际之和）

## 三大航合计：为什么必须先加总再算同比

**Big 3 Total = 三家绝对客运量先加总，再对加总值算同比。**

**简单平均三家的同比是错口径**——旧 skill 曾经写错过这一条，所以这里显式记一笔。
`modules/industry_data/str_source.py` 里有专门的测试断言「按天平均会给出不同的数」，
是同一类错误的另一个面。

自检锚点（2026 年 5 月真实值，换年度重建块或人工核对时拿它对）：

| 指标 | 值 |
|---|---|
| 民航局 · 国内 | -8.06% |
| 民航局 · 国际含港澳台 | +0.08% |
| 三大航 · 国内（Big3 Total） | -9.30% |
| 三大航 · 国际含港澳台（Big3 Total） | +1.07% |
