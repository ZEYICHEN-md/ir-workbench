# 检索配方与参数级禁令

> **迁移说明（2026-08-25）**：从旧仓 `references/decisions/ADR-002-chinese-retrieval-method.md`、
> `ADR-005`、`data-sources.md` 召回保障节搬入。第一次迁移只搬来了一条 `time_range=week` 的坑，
> 把整套「哪个引擎配哪种问法」的禁令漏了。
>
> **漏了会怎样：本次会话现场重犯过。**我用中文描述式 query 喂 tavily 查 8/17–8/23 的国内动态，
> 返回的是 2023–2025 年的行业综述——正是下面那张表里记着的失效组合。

## 顺序不能乱

**先枚举 → 再类目补充搜 → 再描述式补充 → 最后按矩阵核对。**

开放式盲搜召回质量差，所以搜索只做补充。`ir news recall` 负责第一步（Skift + 36氪 RSS 枚举），
其余三步是 Agent 手动跑。

## 文章日期只负责发现，事件日期负责归期

RSS 与搜索的发布时间过滤只用于形成候选池，**不能证明事件发生在情报主周**。读原文后必须回查
事件发生日、首次可靠披露日、实质进展日与文章发布日期，并在成稿审计表里逐条说明归期依据。

- 默认按事件发生日归期。
- 只有本周首次可靠披露、本周出现实质进展、或本周正式发布报告/财报，才可按对应日期归入本周。
- 事件早已公开、本周只是媒体复盘、券商估算或分析旧数据，不收作本周新事件。
- 周末发生、下周一才报道的事件仍归事件发生周；只有周一才首次可靠披露时，才可按“首次披露”例外处理。
- 每条都要回答“本周新增了什么信息”；文章发布日期不得单独作为答案。

## 引擎 × 问法：对照实验（旧仓 grilling 实测）

同一目标「本周境内 OTA 动态」：

| 手法 | 结果 |
|---|---|
| tavily 锁 4 域名 + 多关键词 | **0/2/0，失效** |
| tavily 锁 4 域名 + 单主题短词 | 只回列表页 / 首页，无正文 |
| tavily 不锁域名 + 单主题短词 | 出货，但混大量低质 SEO 稿 |
| tavily 锁 4 域名 + **中文描述式** | **0 条** |
| tavily 不锁域名 + **中文描述式** | 几乎全噪音（被描述句里的词带偏到芯片、美股、招聘） |
| **exa + 中文描述式** | 质量碾压，精准命中境内竞对与行业稿 |

## 由此得到的硬规则

1. **描述式 query 只喂 exa，不喂 tavily。**——SKILL 里「用 exa / tavily 各跑一遍」
   指的是各跑**各自适合的问法**，不是同一句话喂两边。
2. **tavily 只用短关键词，且不锁死域名。**「tavily 中文侧必须锁四源」这条旧硬约束
   已废弃——它正是召回坍缩的元凶。
3. **tavily 禁用 `time_range=week`**（实测国内新鲜稿 0 条）。用 `month` 或不限时，
   再本地按日期筛（`recall.filter_by_window()`）。
4. **tavily 的 `topic` 参数只接受 `general`。**
5. **exa 没有可靠的服务端时间过滤**，结果一律过 `filter_by_window()` 按窗口筛。
6. **不要开放式盲问**（「本周 Booking 有什么大新闻」「OTA 行业动态」）。
   firecrawl 与 tavily 英文侧都验证过：返回的是行情页、社媒、SEO 榜单、
   「OTA Market 2023–2029」这类市场研究报告，捞不到当周事件。
7. **跨源补细节要用「实体 + 事件词」定向查**（如 `Tongcheng Dida acquisition`），
   对**已发现的事件**补材料角度，不用来做发现。

## 两类检索目标，B 类必须放开域名

`ir news recall` 的枚举只覆盖 A 类。**B 类要靠 Agent 手动放开域名扫**。

### A. 行业与公司动态（每期主力）

锁行业域名：`skift.com`、`phocuswire.com`、`traveldaily.cn`（环球旅讯）、
`latepost.com`（晚点）、`36kr.com`、`huxiu.com`、`reuters.com`。
备选 `airlineweekly.skift.com`、各公司 IR 页。

### B. 旅行中断 / 外部冲击（**别锁行业域名，否则整类漏**）

极端天气与自然灾害、交通中断（机场关闭、航班大面积取消、铁路胀轨限速停运、
航司系统宕机）、罢工（航司 / 机场 / 铁路 / 海关）、签证与边境入境政策变化、
地缘冲突与安全事件、大型活动赛事对客流的冲击。

这类**直接影响出行需求与运力**，但不是每周都有——**命中重大事件才收，没有就不收，
绝不为凑数硬塞**。

放开到综合 / 财经 / 交通媒体：`reuters.com` `apnews.com` `bbc.com` `theguardian.com`
`lemonde.fr` `cnn.com`，加 `traveldaily.cn`。

关键词示例：`europe heatwave rail disruption`、`airport closure flights cancelled`、
`travel disruption strike`、`China outbound visa policy`。

> **为什么必须单独提醒搜 B 类**：这类事件常不在行业媒体覆盖内。反例——2026/06 末
> 欧洲热浪致多国铁路胀轨停运，是出行大事件却不算「OTA 科技新闻」，只锁 Skift / PhocusWire
> 会整条漏掉。
>
> 情报库里已有「台风红霞致香港机场约 350 航班取消」一条，证明这类确实该收，
> 而当前的枚举层根本不去找它。

## 覆盖矩阵（每期核对一遍）

枚举 + 类目补充 + 描述式补充都跑完之后，按**实体 × 事件类型**核对本期扫过没有：

- **直接竞对 / 平台**：Booking、Expedia、Airbnb、Agoda、美团、同程、飞猪、MakeMyTrip、Traveloka
- **国内流量与分发入口**：字节系（豆包 / 抖音来客）、阿里系（千问 / 飞猪）、腾讯系
- **酒店集团**：Marriott、Hilton、Accor、IHG、华住、锦江
- **航司与分销**：三大航、主要国际航司、Amadeus / Sabre（GDS）、Google Travel
- **事件类型**（评估视角，不是 query 关键词）：并购融资、财报、产品与战略、
  监管上市与资本、AI 与分发渠道商业化、酒店佣金与渠道政策、高管变动

**规则**：重点竞对与国内分发入口每期确认「扫过」；**没命中要记「扫过无事」**。

这道核对与 `competitor_intel/vocab.py` 的名单是两回事：那份名单管**沉淀时打标**，
这份矩阵管**采集时别漏**。建档层里 MEITUAN / TCEL / FLIGGY 长期 0 条，正需要这道核对
来区分「真没事」和「压根没搜」。

## 信源多样性：防锚定

选稿**只论质量与相关性，不设信源配额**——Skift 强就多用，绝不为「平衡信源」硬塞弱稿。

但**检索侧要多样**：主动纳入 PhocusWire、环球旅讯、晚点、Reuters 命中的优质稿，
别一水儿全是 Skift。定稿前扫一眼信源分布——「谁强用谁」没错，但要**看见**这个集中度，
别无意识锚定。

> 当前 `ir news recall` 只有 Skift + 36氪 两个 RSS 源，锚定风险比旧仓更高。
> `2026-08-W3` 那期的来源说明里已经自承「本期中文侧覆盖较薄」。
>
> ⚠️ SKILL 里那张「源可用性」表只说明**哪些源有 RSS**，不代表其余源不该检索。
> 环球旅讯 / 晚点 / 虎嗅 RSS 拿不到，但它们仍是**检索目标源**。
