# 选稿与写作规范

> **迁移说明（2026-08-25）**：从旧仓 `references/writing-style.md` 与
> `data-sources.md` 选稿节搬入。第一次迁移只搬来了骨架（有哪几节、每条什么形状），
> 漏了**判据**（怎么排序、图标什么语义、概览多长、什么词不许用）。
> 读新 SKILL 不会觉得缺什么——这类漏迁比整份文件不见更隐蔽。

## 选稿分三步，别混为一谈

相关性标尺解决「切不切题」，硬事实门解决「像不像新闻」，评估解决「够不够重、够不够好」。

### 第一步 · 过滤（二值：进 / 不进候选池）

外部事件 vs 携程自家发声、弱相关、跨期重复。
携程当事方边界见 [SKILL.md](../SKILL.md) 的「选稿边界」。

### 第二步 · 硬事实门（二值：能否独立成条）

必须能用一句具体的话回答「**谁在本周做了什么**」，并至少有一组可核验事实——
数字、交易、合作、产品、监管决定、组织变化，任一。

趋势分析或高管访谈如果只有抽象判断、没有明确动作和证据，**只能作背景，不得单独成条**。

### 第三步 · 评估（在候选里相对排序）

三把尺，各打粗档（高 / 中 / 低）**并配一句理由**：

| 尺 | 问什么 |
|---|---|
| 重要性 / 体量 | 涉及金额或份额多大？结构性变化还是增量小事？动没动携程的可寻址市场或分发格局？ |
| 事实密度 / 信息增量 | 有几个可核验的新事实与数字？读完能否明确知道本周比上周多发生了什么？ |
| 质量 / 信源 | 原发深度报道，还是二手转述或 PR 通稿？（来源可靠 ≠ 单篇信息密度高，两者分开判） |

**决策规则**：

- 硬事实门不过 → 不独立成条
- 双低 → 不收
- 其余按三把尺**相对排序**，取 top 6–10
- **淡周宁可只收 4–5 条，不把 6–10 当配额**
- **用相对排序，不打精确分**——不给「3.6 vs 3.4」这类虚假精确。每条评级配一句理由，
  理由必须点明「新动作 / 证据是什么、为什么重要」

## 定稿前自检

判断不写死成关键词规则（会误杀、太脆），而是要求**把判断显式说出来**——
articulation 本身就能提升判断稳定性，也让人能复查纠偏。

### 逐条（每条都要能答上）

1. **是竞对 / 行业，还是携程自己？**
2. **一句 so-what？**对携程或 OTA 格局意味着什么？一句话说不出＝弱相关，降权或不收。
3. **跨期重复？**跑 `ir news check`，命中就剔除或按「实质跟进」标注。
4. **重要性 × 质量评级？**各配一句理由；双低不收。

### 全批（一次性确认，堵「整类漏 / 信源单一 / 溯源错配」这些静默失误）

- [ ] **覆盖矩阵重点竞对都扫过**（见 [retrieval.md](retrieval.md) 的矩阵）
- [ ] **旗舰源完整性对账过**（`ir news recall` 枚举与补充检索对了账）
- [ ] **B 类外部冲击也搜了**（放开域名扫过中断 / 罢工 / 签证 / 天气 / 地缘；
      没命中重量级事件属正常，但要确认**搜过**，别整类漏）
- [ ] **信源分布扫一眼**（是否清一色 Skift？「谁强用谁」没错，但要**看见**集中度）
- [ ] **每条 title ↔ URL 自洽**（曾出现标题是世界杯、URL 却指向另一篇 STR 分发稿的错配。
      现在 `ir news validate` 会硬查条目数 = 来源表行数，但**配对内容对不对仍靠人看**）

### 检索留痕（必做，但极轻——写进交付汇报即可，不新建文件）

1. **跑了哪些查询**：A 类主题 + 锁的域名；**B 类放开域名扫的关键词**——
   哪怕没命中也要写「B 类扫过、无重量级事件」。
   目的：下周若漏了，第一时间能查「到底搜没搜」，而不是「搜回来的里有没有」。
2. **边界取舍**：一行列出有意识砍掉的边界条 + 理由。明显无关的不必记。

> **明确不做：完整候选池落盘。**理由三条：①它瞄准漏报却抓不住——真正漏掉的事件是
> 「压根没进候选池」的，落盘只记录搜回来了什么，漏的那条也不在日志里，给的是虚假安心；
> ②候选日志是 Agent 自产、drop_reason 是事后合理化，记烂判断不会让它变好；
> ③没人会去读那个文件，是死重量加维护漂移。**防漏报靠上面第 1 条的查询覆盖，不靠落盘。**
>
> 这条是「明确不做」的决策，写在这里就是为了防止以后有人热心加一套留痕机制。

## 本周概览怎么写

紧跟 `## 一、` 之后，**约 3 句**（现在用 bullet，旧仓是一段引用块——格式有意改过，
判据不变）。

- **精简**：几条主线各一句话带过（「OTA 侧…；酒店侧…；需求侧…」），别写成一大段。
- **就事论事，别假大空**：一周新闻而已，**不要动辄「重塑行业」「标志性转折」这类大帽子**。
  平淡的一周就如实说「本周多为渐进动作、无重大突发」。
- **论断与事件体量相称**，不确定的别硬拔高。

## 图标语义（每条只配一个，别堆叠）

| 图标 | 用于 |
|---|---|
| 📬 | 报告头 |
| 🏨 | 酒店 / 酒店集团 |
| ✈️ | 航空 / 航司 |
| 🤖 | AI |
| 🚀 | 平台并购 |
| 🏢 | 公司动作 |
| ⚠️ | 监管合规 |
| 🌍 | 出海 / 跨境需求 |
| 🚨 | **旅行中断与外部冲击**（天气、机场铁路中断、罢工、签证边境、地缘安全） |
| 🚆 | 纯地面交通（铁路、公路） |
| 🎫 | 体验与票务（2026-08-25 增补） |
| 💳 | 支付与费率经济（2026-08-25 增补） |

**趋势标注只用三个：📈 上升、📉 下降、⚠️ 告警。**这三个是趋势专用，
**不要拿来当话题图标**——`2026-08-W3` 初稿曾用 📈 标 Airbnb 营销、📉 标 Booking，
那是把两套语义混在一起，读者会以为在标涨跌。

> 增补两个图标是因为交付物比旧仓的五章周报覆盖更宽（体验品类、支付经济）。
> **增补要显式改这张表**，不要临场挑一个了事——图标一期一变会让观感散掉。

> 为什么值得规定：图标随手挑会让观感一期一变，而**一致的风格本身是可信度的一部分**
> （旧仓原话）。

## 正文写法

```
**{图标} {中文标题——先写清主体在本周做了什么}**
{第 1 句：主体动作；第 2 句：期限 / 金额 / 人数 / 增速等关键证据；第 3 句：对行业或携程的 so-what}
```

- **标题加粗自成一行**，后空一行再写分析（纯换行会被 Markdown 合并成一段）。
- **不自动加粗数字。**只给**趋势与转折**（监管转向、渠道变化、量价走弱）用 `**` 标出。
  导出脚本还会自动识别常见转折短语——所以人写稿时不要再手动重复加粗。
- **不放英文原标题、不放英文金句、正文不放来源链接**，统一进来源表。
- **不设 `###` 分类小标题**，逐条平铺，按对携程相关度与事件体量排序。

## 语气

**客观、克制、结论先行。**每条点出「这件事对行业或 OTA 意味着什么」，
**而不是复述**。

结构对了语气仍可能跑偏，而 so-what 恰恰是人写的那部分——这条不是废话。

## 「延续上期」是规则，不是可选写法

同一事件的实质跟进可以收，但**必须**在标题或首句标「延续上期：…」，
并且**不重复叙述已写过的内容**，只写增量。

不立成规则的后果：跟进报道会被当成新事件重写一遍，读者看到两期几乎一样的稿子。

## 表格与数字

- 表格必须是合法 Markdown；空数据保留表头并写「暂无数据」，不要删表。
- 百分比与百分点分清：比率变化用 **pp**（百分点），相对变化用 **%**。
- **宁缺毋造**：抓不到来源的条目丢弃，不猜、不脑补（见 `conventions/data-provenance.md`）。
