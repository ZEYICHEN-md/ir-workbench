# ADR 0004 — 卖方研报保留为轻量内部查询能力，不进情报库

- 状态：**Accepted**（2026-08-22）
- 日期：2026-08-22

## 背景

原「五部分旅行行业周报」的第三节是「卖方行业跟踪」。周报停用后这块没有归属。

现状说明问题：`0703_Travel_Pulse/inputs/2026年7月第4周/` 里有 BofA 航空、UBS 铁路、MS 港股休闲、UBS 酒店 first read 四份 PDF 加一份 editorial brief，但那一周只产出了新闻精选——**研报进来了，没出去。**

需求方描述：「有时候会想去采集来看看，但不是什么特别重要的需求。」

## 考虑过的三个选项

1. **彻底停用**——研报只人工读，不进系统。
2. **并进竞对情报库**——作为条目来源之一。
3. **保留为轻量内部查询能力**——按需摘读，不建持久档案。

## 决策

取选项 3：**保留为内部查询能力，与港股同一待遇。**PDF 放进来、Agent 帮读帮摘、按需产出，**不建持久档案，不进竞对情报库。**

### 为什么不并进情报库

- 研报里能进情报库的只有**事实性内容**（转述的管理层口径、公司动作、行业数据），而研报的主要价值是**分析师观点与预测**——这两类情报库明确排除（ADR 0002 §3）。并进去实际只能收一小部分。
- 研报不可外传。条目一旦引用研报内容就带上合规属性，需单独标级、绝不能进公开作品集仓。为一小部分内容引入这套麻烦不划算。

### 为什么不彻底停用

需求方明确说仍会用。停用会制造「系统不支持，于是绕过系统手工做」的路径。

### 为什么不做持久层

持久层有真实维护成本：分层、去重、schema 演进、名单维护。**低频 + 低重要性的能力，做成「随时能查」比「持续沉淀」合适。**这是本 ADR 的一般原则，后续新增能力可复用这条判断。

## 后果

- `sellside-research` 是唯一没有周期键的域（`period_kind = none`），不产生 manifest。
- 研报原件仍进 `inputs/sellside-research/`，但不做跨期索引。
- 若将来研报源消失，此域可整体废弃，不留残余入口。
- 若将来发现确实需要跨季度回查研报观点，须新开一份 ADR 推翻本决策，不得悄悄加持久层。

## 可持续验收证据

真实研报和按页抽取物不进 Git，CI 因而不能重放某份券商报告。持续回归使用完全自造文字的
合成 PDF/模拟页，只验证页码顺序、空文本拦截、临时输出和“不建 manifest、不写情报库”的边界。
真实材料仍用于本地业务验收，但不以保存原文来换取可复现性。具体记录见
`docs/specs/2026-09-03-sellside-research-acceptance.md`。域状态如何表达见 ADR 0008。
