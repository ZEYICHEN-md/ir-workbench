# ADR 0005 — 专家访谈独立成域，并作为竞对情报库第三条采集通道

- 状态：**Accepted**（2026-08-22）
- 日期：2026-08-22

## 背景

ADR 0003 划了七个域。迁移 `database_matain` 时发现漏了一条完整成熟的流水线：

`database_matain/.cursor/skills/expert-call-pipeline/` —— 专家访谈 PDF（飞书链接或本地）→ 抽全文 → 按 `.cursor/agents/expert-call-insights.md` 提取洞察 → 渲染 callout XML → 写入飞书 Wiki「Expert Call 精选」版块。

它已具备的东西：

- **收录门槛**：纯观点、锚定数字少于 4 个 → `include: false`，写入 manifest 备查但不发飞书
- **密度要求**：每段 ≥1 个数字，全文 5–7 个锚定数字
- **排版硬规则**：callout 必须插在三栏 grid 块之后（插在 h2 下会挤在极窄的中间列）
- 自己的脚本（`scripts/expert_call_pipeline.py`）、模板、`config.example.json`、`PORTABLE.md`
- 已产出四篇：Hyatt EMEA 收益管理、前 Expedia 商业运营 VP、Expedia 技术、Tripadvisor

## 决策

### 1. 独立成第八个域 `expert-calls`

不并入 `industry-data`。它的目标（飞书 Wiki 版块）、门禁（锚定数字阈值）、产物形态（callout XML）与行业数据链路毫无重叠；合并只会造出第二套入口。

### 2. 公司情报库是首要沉淀方向，飞书精选是独立展示分支

人类不定期提供专家访谈后，Agent 首先识别其中公开渠道难以获得的行业事实、公司信息、内部经营数据与因果机制，生成带专家原话和 PDF 页码/位置的内部情报草稿。草稿经人工核对并明确确认后，写入竞对情报库。

是否进入飞书精选与是否具有情报价值是两个判断。一篇访谈可能不够形成完整 callout，但其中某项可核对的增量数据或事实仍值得入库；反过来，飞书发布也不会自动触发情报入库。

情报库不要求每项数据先支撑一个现成论点。只要数据或事实本身具有检索价值，相对公开渠道有增量，且时间、口径、原话和位置可核对，就可以留存。支持当前判断、反驳当前判断、与其他来源冲突，或暂时无法形成结论，都不是排除理由；相应限制写入条目的 `body` / `note`。这样可避免把情报库做成只收支持性证据的“论点库”。

| 通道 | 节奏 | 来源 |
|---|---|---|
| 周度通道 | 每周 | 新闻采集 |
| 季度通道 | 财报季 | 电话会、财报口径 |
| **专家访谈通道** | 按访谈到达 | 专家访谈中的可检索数据、事实、表述与机制 |

理由：已产出的四篇访谈对象全是 peers（Hyatt / Expedia / Tripadvisor），内容形态正是「有来源位置的公司数据、事实与表述」——与情报库的 entry 定义天然吻合。沉淀后，季度做竞对研究时新闻、财报口径、专家访谈可一起检索，这正是情报库要解决的「省掉回溯采集」。

条目映射：访谈里的公司动作 → **动作**条目；专家对某家做法的转述与判断 → **表述**条目，来源标为访谈（含 PDF 名与段落位置）。

### 3. 敏感度：内部

AlphaSense 类专家访谈的敏感度高于新闻。所有由本通道产生的条目默认标**内部**级，不进公开作品集仓，访谈 PDF 原件不进 git。

### 4. 两类产物各有权威

访谈 PDF 是原始证据；确认写入后的 JSONL 是公司情报库真源，公司档案是其投影。飞书 Wiki 仍是精选摘要的权威稿，但它只负责展示，不是情报入库的前置条件，也不能反向替代 PDF 原话。

### 5. 实施增补（2026-09-01）

迁移时以目标 Wiki 的 **revision 1680** 只读回读为准，确认旧本地模板已漂移。唯一有效结构是：

```xml
<callout border-color="rgb(239,240,241)" emoji="📌">
  <p><b>标题</b></p>
  <p><em>专家背景：...</em></p>
  <p><em>时间：...</em></p>
  <blockquote><p>...</p></blockquote>
  <p><em><span text-color="rgb(143,149,158)">更多详情请见：</span></em>飞书文件裸 URL</p>
</callout>
```

旧模板的浅蓝 `background-color` 与 `<bookmark>` 作废。标题仍是三栏 grid 中的红色居中 h2，
callout 必须插在**整个 grid 后**。锚点每次运行时解析，不能把 block id 写死。

- 运行索引采用 `YYYYMMDD-HHMMSS`，避免原 `period_kind = none` 无法追踪批次。
- PDF 用 `pdfplumber` 按页抽取；空文本/扫描件硬停并要求 OCR，真实 PDF/TXT 不进 Git。
- 发布默认 dry-run；只有用户明确说「发布专家访谈精选」才写飞书。
- 写入前按精确标题或 PDF 链接判重；每写一条立即回读，取得新 block id 后再插下一条。
- 中途失败返回 `partial` 并保留已写 block ids，重跑时依靠精确判重跳过已完成项。
- 情报草稿在本地解析后即可独立生成，不读取飞书，也不以 `include = true` 或发布成功为前提。草稿仍需另行确认才入库。`channel = expert-call` 一律强制
  `internal`；所有专家访谈情报条目都必须保存原话和 `PDF 文件名 + 页码/位置`，摘要转述不得冒充原话。

### 6. 精选排序先于人工收录（2026-09-01 业务校正）

旧流程把“数字、因果机制、相关信息增量三项满足两项”作为二元准入门槛，且沿用了旧 Agent 中
“携程 / 中国出境 / B2B / AI”的相关性表述。业务复核后确认：**B2B 并非携程 IR 的独立关注方向**；
只因提到 B2B 不应提高收录概率。

新流程先为整批访谈生成供人选择的排序报告，再决定 `include`：逐篇展示一句话概述、关键数据、
高参考意义的行业事实与洞察、专家来源与职能、证据局限，以及 IR 相关性、信息增量、专家权威、证据质量、因果深度、时效性
六维评分。代码按固定权重计算 A/B/C 档，并增加信息增量上限：`information_gain` 为 0–1 分时最高 C，2 分时最高 B，只有 3 分及以上才允许进入 A，避免专家身份或议题相关性把与财报、电话会大体重复的内容抬进精选首档。公司规模与战略市场相关性分开：大型跨国平台/集团可进 A，有规模的多市场公司最高 B，区域性/细分公司通常最高 C；但若直接覆盖 Trip.com 国际扩张重点的中国或亚太市场，最高可到 B。单体酒店和本地小公司最高 C。排序不替代人工判断；`include` 可在候选阶段保持 `null`。

直接 IR 信息增量改为收录硬门槛，范围收敛为携程经营、中国及跨境需求、全球 OTA 竞争和 AI
旅行分发。亚太竞争映射明确把 Agoda（Booking Holdings 旗下）和 Traveloka 视为 Trip.com 的重点直接竞对：Agoda 相关业务专家同时具有全球平台背书和亚太直接相关性；Traveloka 专家可获得高亚太相关性，但来源规模仍按多市场公司单独评估。B2B 只有在显著影响竞对增长、利润率、渠道黏性或 AI 防御时，才作为经营机制保留。
人工选中后才校验最终 manifest、渲染 callout；飞书确认门禁不变。

### 7. 专家数字按“主张”保存，不作为可覆盖的真值（2026-09-01）

专家数据采用两层语义：JSONL 保存的是“某来源在某时间、某口径下提出的 claim”，不是系统认定的 canonical 数值；综合判断由查询或人工研究阶段形成。独立数据不需要先绑定论点，但必须拆成可比较的原子 claim，记录稳定 `metric_key`、结构化范围、数据期、值、单位、比较口径、证据类型、来源距离及置信度理由，并保留原话与页码。

入库预演相对当前库动态分成「新增、佐证、冲突、疑似口径不同」。只有指标、数据期、范围、单位与比较口径可比时才判断数值佐证或冲突；不能安全比较时不得自动换算或合并。所有主张采用 append-only：新来源不覆盖旧值，冲突双方均保留，系统不自动裁决。冲突分类是随当前证据变化的关系，不固化为条目永久状态。低置信度 claim 仍可检索，但其置信度与限制必须显式返回。

### 后果

- 旧的普通情报条目不强制回填 claim；出现高价值可比数据时再按需补。
- 同一 PDF 中多个指标使用 claim 口径参与稳定 ID，避免共享来源 URL 导致错误去重。
- 公司档案投影暂不展示动态冲突结论；冲突在 `intel add` 预演中审查，避免把相对状态写成永久事实。

## 后果

**好的：**
- 专家访谈不再只沉在飞书 Wiki 里，季度研究可检索。
- 情报库多一条高质量来源——访谈的数字密度门槛本来就比新闻高。

**要接受的：**
- 情报库需要区分条目来源（新闻 / 财报 / 访谈），且敏感度按来源分级，不能一刀切。
- 情报分支是访谈到达后立即发生的独立采集流程；飞书精选只是第二条展示分支，两者分别确认，不互相触发。
- `expert-calls` 的飞书目标 doc token 与版块位置是硬编码的外部依赖，飞书侧改版会打断流程，须写进 runbook。
