# IR 工作台 — 术语表

> 只放工作台层面的统一语言。各域内部术语留在各自的 `CONTEXT.md`。
> 体例：**术语** + 定义 + *Avoid*（不要用的说法 / 常见误解）。

## 产品与角色

**IR 工作台**
携程 IR 部门的 AI 自动化工作台。以 Agent 为入口，把部门高频工作沉淀为可分发、可移交、可持续使用的系统。产品边界由八个域定义，当前按 `docs/MIGRATION.md` 分阶段迁入。
*Avoid*：把它当成三个独立项目的文件夹集合；把它叫作「脚本库」

**业务接手人**
原作者离职后接手日常运行的部门同事。**非技术背景**：不写代码、不进终端、不用 git、不读 traceback，只用自然语言与 Agent 对话。业务判断能力强（例如本来就很会写 Appendix），缺的是操作能力。
*Avoid*：假设他会跑命令、会看日志、会自己打包；把「给了文档」当成完成移交

**对外交付物**
会发给部门外的人看的产物。当前只有一个：**旅行行业新闻精选**。对外交付物的验收门禁最严。
*Avoid*：把内部查询结果直接对外发；同时存在多个对外周报产物

**内部查询能力**
部门内部想了解时才调用、不产出对外文档的能力。当前包括：港股市场数据（行情 + 南向持股 + 港美成交占比全套）、行业数据看板与洞察、竞对情报检索。
*Avoid*：为内部查询强行套一份「周报」外壳；把内部能力算进对外交付节奏

## 入口与分层

**顶层路由**
人的唯一入口。业务接手人只说自然语言（「做这周新闻精选」「更新国内行业数据」「BKNG 出财报了」），由路由归类意图并分派到对应域。
*Avoid*：让接手人记命令；把 CLI 当成人的入口；多个并列的自然语言入口

**Control Plane**
Agent 的手。工作台 CLI 与 manifest 系统，负责环境预检、当前文件配置、运行状态、完整性门禁。**只被 Agent 与 Operator 调用，业务接手人永远看不到。**
*Avoid*：把 CLI 写进面向接手人的操作手册；因为「同事不会用命令行」就不做内核

**首次安装包**
解压即用的 zip，只解决第一次装。
*Avoid*：把 zip 当唯一分发形态；指望接手人自己重新打包

**持续更新通道**
首次安装之后的版本更新路径：GitHub 私有仓 + Agent 代跑拉取。接手人不碰 git。
*Avoid*：靠飞书群里发新 zip 做版本管理；两个同事手里跑着不同版本而无人知晓

**公开作品集仓 / 内部工作仓**
两个分开的 GitHub 仓。公开仓只含代码与框架，用于对外展示；指标底稿等获准版本化的数据只在内部私有仓。STR、券商研报、专家访谈、财报原件等第三方或敏感材料只放本机 Git 忽略目录或其原始授权系统，**不进入任何 Git 历史**。
*Avoid*：临到 push 时才想数据脱敏；把真实 PDF/TXT 推进内部仓后误以为“私有就安全”

## 数据

**指标底稿**
`国内行业数据_MMDD.xlsx`。国内行业指标的**唯一人工编辑面**，也是**唯一指标真源**。人工填写与自动化写入（航空月度、酒店 STR）都汇合在这一张表。全工作台只有一份，不在多处各存一份。
*Avoid*：主库、中间层、Excel 镜像；两个域各存一份副本；把它叫「入口」并暗示它不是权威

**人手填的值优先**
底稿**内部**的权威层级：人手填的数字最高，自动化只能填空格，不能覆盖已有值。自动化提供的是一种取数方式（如从中金周报聚合月度），不是新的权威源。
*Avoid*：把「算得更准」当成可以覆盖的理由；为了口径统一去回改历史值；把自动化来源说成权威

**底稿归档**
`data/workbooks/archived/`。两种东西放这里且**只增不删**：换新版底稿时的旧版（`国内行业数据_0817.xlsx`）、每次自动写入前的整份备份（`*.pre-<动作>-<时间戳>.xlsx`）。
*Avoid*：换新表时删掉旧表；只靠 git 留版本（接手人不会用 git）；清理归档腾空间

**指标快照**
`travel.json`。指标底稿的机器投影，可随时从底稿全量重建，**不接受手改**。用于驱动看板与飞书投影。
*Avoid*：canonical 权威、主库；手改快照来修正数字；把它和洞察底稿混为一个「canonical」概念

**洞察底稿**
`travel-insights.json`。独立真源，由人确认后入库，与指标底稿无关，不随指标重建而变动。指标更新后若未按新数据重新确认，会被标为**可能过期**，看板上会显示提示；不自动重写。
*Avoid*：把洞察塞进指标快照；重建指标时连带覆盖洞察；数字一同步就自动改写洞察

**春节(日均)**
底稿周度区里的节日日均行，与同区周度同口径。它**不是**标准 `M/D-M/D` 周次，推断数据截至日时要跳过它，但作为时间标签照常入库。旁注「民航局日均」只针对航空客运量列，不改变酒店三列含义。
*Avoid*：当成异常行跳过不收；把它算进最新周结束日的推断

**周次标签（去前导零）**
周度时间标签统一为无前导零格式（底稿里 `6/07-6/13` → `6/7-6/13`）。飞书已有行、底稿左右两块、看板都认这一种写法，写法不一致会导致配对失败。
*Avoid*：照抄前导零；同一份表里混用两种写法

## 看板与发布

**看板半公开托管**
看板以公网 HTTPS 静态站发布（**https://datamax.fun**），**不做登录鉴权**，靠链接分发（飞书文档嵌入、微信分享），不主动做搜索引擎收录。验收口径：办公室（新加坡出口）与国内手机微信都要能打开。
*Avoid*：当成内网站点；当成完全私有的数据；把源码仓可见性与站点可访问性混为一谈

> 这条同时是**数据边界**：看板四文件的内容事实上公网可取。但「不主动收录」意味着**不主动扩大传播** —— 把它放进公开作品集仓属于扩大传播，须另行裁决。

**看板展示精度**
看板所有百分比一律展示一位小数（KPI、轴标签、图上标注、tooltip 都一样）。底层快照仍存完整小数同比，**不因展示取整改写权威值**。
*Avoid*：轴用整数、KPI 用两位；为了好看回写快照

**仅填空不覆盖**
飞书投影的写入规则：已存在的行只填当前为空的格，已有非空值一律保留，即使与快照不同也不改；可新增飞书尚无的时间行。dry-run 必须列出「飞书已有值 ≠ 快照」的冲突行让人知晓，默认仍不覆盖。
*Avoid*：整行替换；按快照静默校正历史格；dry-run 隐瞒分叉

## 竞对情报

**竞对情报库**
按公司与主题累积的 Global OTA 与国内 peers 动态存储。周度由新闻精选副产品沉淀，季度供竞对研究与季报定位检索。JSONL 为真源，各公司 markdown 档案为人读投影。设计见 `docs/adr/0002-competitor-intel-store.md`。
*Avoid*：把它当成新闻归档；沉淀时重写摘要；把它和 `news_ledger.py` 的去重台账混为一谈（后者只管本期查重）

**动作条目 / 表述条目**
**动作**记录「做了什么」，来源为新闻、公告、公开动作。**表述**记录「怎么说的」，存原话引用加位置（页码 / 时间戳）。做 IR 定位时表述常比动作更有用；专家访谈表述的位置必须精确到 PDF 文件名和页码/段落。
*Avoid*：只收动作；把原件搬进情报库；把摘要转述冒充原话

**建档层 / 索引层 / 其他桶**
覆盖名单的三层。分层依据是「要不要建独立档案」，不是重要程度。建档层每期必扫、各有档案；索引层打标签可检索、Appendix 里主要靠财报材料；其他桶只存不维护。名单见 ADR 0002。
*Avoid*：按「重要 / 不重要」分层；随手往建档层加公司

**主角 / 提及**
一条动态里被记为主角的公司进其档案正文，仅被提及的只进检索索引。**这是放置规则，不是入库过滤器**——两者都记录。
*Avoid*：把「只是被提及」当成不值得记录

**主题受控词表**
情报条目的主题维度只能取自固定词表（见 ADR 0002 §7）。跨公司横切检索依赖它，自由标签会让横切失效。新主题须显式增补。
*Avoid*：自由打标签；同一件事在不同公司条目下用不同措辞归类

**三条采集通道**
**周度通道** = 随每周新闻采集沉淀，覆盖全部名单（含 TCOM），成本近零。**季度通道** = 跟财报季采集表述条目，覆盖建档层的电话会与财报口径。**专家访谈通道** = 专家访谈 callout 获准写入飞书后生成情报草稿（ADR 0005）；草稿仍须单独确认才入库。后两条是真的额外一步，不是副产品。条目敏感度按来源分级：访谈条目强制内部级。
*Avoid*：假装季度通道与访谈通道也是副产品；把生成草稿说成已经入库

**专家访谈候选排序**
整批访谈进入 callout 草稿前的人读评审层。逐篇展示主题概述、关键数据、行业事实/洞察、专家来源与职能、证据局限和六维评分，代码只计算 A/B/C 建议档；`include: null` 表示等待人决定。直接 IR 信息增量和 4 个锚定数字是硬门槛；大型跨国平台相关业务高管优先；区域来源降低背书，但直接覆盖 Trip.com 中国或亚太重点市场的信息最高可保留 B 档；单体酒店与非重点区域小公司受 C 档上限；B2B 不单独构成相关性。
*Avoid*：把排序当自动收录；只给一个总分不解释依据；候选排序后直接写飞书

**Expert Call 精选 / 飞书权威稿**
目标 Wiki 中红色居中 `Expert Call 精选` 标题下、整个三栏 grid 之后的全宽 callout。飞书线上内容是权威稿；本地 XML 只是待发布草稿。版式真源为线上 revision 1680：灰色边框、📌、标题/专家背景/时间、blockquote 段落和裸 PDF URL。
*Avoid*：沿用旧浅蓝背景或 bookmark 模板；把 callout 插进中间列；把本地 XML 当权威

**专家访谈情报库投影**
由已发布访谈生成的检索草稿。它不是摘要正文的复制，也不是访谈权威稿；表述条目必须带原话 `quote` 与 `PDF 文件名 + 页码/位置` 的 `quote_where`，确认后才可入库。
*Avoid*：把摘要转述填进 quote；发布飞书后自动静默入库

**内部敏感度（专家访谈）**
凡 `channel = expert-call` 的情报条目，不论涉及哪家公司，都由代码强制 `sensitivity = internal`。真实 PDF/TXT 只留在 Git 忽略目录或飞书，不进入 Git。
*Avoid*：只在提到 TCOM 时才标内部；让调用方用 `shareable` 覆盖来源级门禁

**Ticker 词表**
`TRIP` = Tripadvisor；`TCOM` = Trip.com / 携程。两者绝不用 `Trip` 缩写。
*Avoid*：沿用 `peers_rs_update/CONTEXT.md` 里「MMYT/TRIP/途牛」这种可被误读为 Trip.com 的写法

**采集不设限，发布设限**
TCOM 在情报库里与其他建档公司同等待遇，动作与表述都收。限制只在发布侧：**新闻精选不得出现任何 TCOM 的动作与表述**。情报库反向为精选供料时，TCOM 条目必须排除。TCOM 条目默认标内部敏感度，不进公开作品集仓。
*Avoid*：在采集侧把 TCOM 排除掉（会让它的档案失去唯一低成本来源）；因为情报库里有 TCOM 就顺手写进对外精选
