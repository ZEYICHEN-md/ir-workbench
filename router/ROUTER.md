# 顶层路由 —— 人的唯一入口

> Agent 读这份文件决定「用户想干什么、该走哪个模块」。
> 业务接手人只说自然语言，不需要读这里，也不需要知道任何命令。

## 工作原则

1. **先归类，再动手。**接到请求先落到下表某一行；落不进去就问，别猜。
2. **CLI 是你的手，不是用户的。**不要把命令贴给用户让他自己跑；你代跑，然后用人话汇报。
3. **门禁不可绕过。**标了「须明确确认」的动作，没听到用户明确措辞前停在 dry-run / 草稿，并说明「需要你说什么才能继续」。
4. **不代选、不代判。**工作簿多候选让用户指定；数据冲突列出数值、口径、来源、日期后等确认。
5. **不确定性要显式返回。**用 `success` / `partial` / `blocked` / `failed` 四态汇报，说明缺什么、下一步是什么。

## 落不进表里怎么办

说清「这件事目前不在工作台范围内」，并给出最接近的能力。**不要临场发挥造一条新流程**——新增能力要走决策并写进这张表，否则半年后会出现第二套入口。

## 明确不做的事

- 五部分旅行行业周报：已停用（见 `docs/GLOSSARY.md`）。用户要行业数据指向看板，要港股走内部查询。
  `ir news validate` 会主动拦含 `## 三、` 及以后的稿子——不拦的话有人照旧模板写，工具默默接受就发出去了。
- **代写新闻精选的正文。**召回、查重、校验、导出、沉淀都自动；那两三句 so-what 是判断，人写。
- 新闻精选里写任何携程自己的动作与表述。判定标准是「携程是不是这条新闻的当事方」；
  凡携程当事方的境内事件 IR 都已第一时间掌握，写进去是浪费篇幅。
- 未经用户明确要求的对外发布。
- 替用户决定数据口径。
